# 作业 4 · C 路径反思（约 300 字）

对照 LangChain 官方 2-Step RAG 与 Datawhale llm-universe 的 C3/C4 后，我更清楚自己这套 `rag_qa.py` + `assistant_v1.py` 已经覆盖了流水线的主干：加载分块、向量入库、检索、拼提示生成、以及用幻觉对照做朴素评估。官方示例强调「组件可替换」——换 embeddings、换切分参数、换生成模型，接口形状不变；我这边用 `prefer=local|api` 和 `use_rag` 开关，其实就是在做同一件事的最小版。读文档时也看到自己省掉的部分：没有正式的评估集与指标、没有 UI/服务化部署、检索策略仍是简单 top-k，也还没让模型自己决定「要不要检索」（那是下周 Agentic RAG 的方向）。C 路径不要求改代码，但对照之后有一个明确的迁移点：数字类、标准类问题必须走检索，创意类活动设计可以裸答再人工改。把「官方五步 ↔ 我的五行」写进 `rag_pipeline_map.md`，是为了以后改 v1.1 时知道该动哪一层，而不是推倒重来。
