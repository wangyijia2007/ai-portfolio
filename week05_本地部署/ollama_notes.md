# W5 本地部署笔记（Ollama）

## 1. 安装步骤（按本机实际踩坑写）

1. 官网 `https://ollama.com/download/windows` 下 `OllamaSetup.exe`。  
   **坑 1**：`winget` / 直连 GitHub release 极慢甚至超时，改用 `curl` 拉官网 CDN 安装包后静默安装才成功。
2. 装完先确认服务是否起来：
   ```powershell
   ollama --version
   # 本机：ollama version is 0.40.6
   curl http://localhost:11434/api/tags
   ```
3. **坑 2**：`ollama pull qwen2.5:0.5b` 约 90KB/s，等不动。改从 ModelScope 下  
   `Qwen2.5-0.5B-Instruct` 的 Q4_K_M GGUF，写 `Modelfile` 再：
   ```powershell
   ollama create qwen2.5:0.5b -f Modelfile
   ollama run qwen2.5:0.5b
   ```
   对话能回、不报错，才算「跑通」。
4. **坑 3**：机房/系统开了 HTTP 代理时，Python `requests` 访问 `localhost:11434` 会被劫持。必须：
   ```python
   s = requests.Session()
   s.trust_env = False
   ```

### 跑通证据：`ollama list` / `ollama ps`

```text
> ollama list
NAME            ID              SIZE      MODIFIED
qwen2.5:0.5b    221e89dfb2e6    491 MB    ...

> ollama ps   （刚对话过之后）

```

说明：本机无独显负载时主要吃 **CPU + 内存**；`SIZE` 列是加载后占用，比磁盘上的 491 MB 略大属正常。物理内存约 **31.5 GB**。

## 2. 所选模型与理由（按内存分档）

| 本机内存档位 | 更稳妥的起步量级 | 说明 |
|--------------|------------------|------|
| 约 8GB | 0.5b–1.5b | 先保证能跑，别一上来 7b |
| 约 16GB | 1.5b–7b 可试 | 仍建议先小后大 |
| 约 32GB | 7b–14b 也吃得消 | 但仍可先用小模型摸清流程 |

| 项目 | 我的选择 |
|------|----------|
| 模型 | `qwen2.5:0.5b`（磁盘约 491 MB，量化后） |
| 本机 | ~32GB 内存，本可选更大 |
| **为何不选更大** | 本周目标是「跑通 + 摸脾气 + 对比云端」，不是追质量上限；0.5b 装载快、适合课堂演示和格式固定任务；更大模型下载/加载慢，出错难排查。先小后大。 |

## 3. 术语：量化 ≠ MCP（课堂抽查用）

- **量化（Quantization）**：把模型权重从高精度（如 FP16）压成低比特（如 Q4），**体积变小、内存占用下降**，往往略损一点效果。我用的 GGUF `Q4_K_M` 就是量化产物——所以 0.5B 参数的模型磁盘只有约几百 MB。
- **MCP（Model Context Protocol）**：是一种让模型**接外部工具/数据源**的协议（像给模型插插件），跟「把权重量化变小」完全不是一回事。  
  一句话：**量化管“模型变瘦”；MCP 管“模型能不能调用工具”。**

## 4. 本地 vs 云端对比（≥5 个学科问题）

同一组问题：本地 = `qwen2.5:0.5b`；云端 = 第 4 周 DeepSeek（`chat_log.txt` / 课堂实测对照）。

| # | 学科问题 | 本地速度 | 本地质量观察 | 云端（对照） | 该用哪个 |
|---|----------|----------|--------------|--------------|----------|
| 1 | 用一句话说明什么是把字句 | 0.33s | 提到“把”，定义不准（写成“连接动作的短语”） | 能说清处置义 / 宾语前置 | **云端**（概念要准）；本地仅草稿 |
| 2 | HSK4 级对词汇量的要求大概是多少 | 2.04s | 胡说「每单元 50 汉字」，与《等级标准》四级累计约 **3245** 不符 | 可贴近标准表述（仍需人工核验） | **禁止裸用本地当标准**；云端+对照原文 |
| 3 | 给《愚公移山》出一道 HSK4 阅读题 | 1.39s | 有格式，内容跑偏（修长城等幻觉） | 更贴课文主旨 | **云端出题 + 人工校对** |
| 4 | 解释送气/不送气，各举一声母例子 | 4.37s | 概念散乱，例子不可靠 | 能讲清 p/t/k 与 b/d/g | **云端** |
| 5 | 扩展 45 分钟教案提纲（周末安排 + 因为……所以……） | 3.93s | 有骨架，语法点融入弱 | 步骤更可上课 | **本地草拟 → 云端润色** |

### 结论

- **本地**：快、免费、断网可用、数据不出机 → 批量模板、格式练习、课堂演示草稿。  
- **云端**：质量更高 → 概念讲解、正式出题、需要可靠知识的任务。  
- **第 6 周**：用 `llm.py` 的 `prefer` 把上述判断写进代码。

## 5. 隐私与脱敏（哪些不该上云）

**默认不要上云的教学数据：**
- 学生作文原文、口语录音转写；
- 成绩单、平时分、学号、姓名、班级通讯录；
- 未公开教案、未发表试卷、校内会议纪要。

**若必须用云端，先脱敏：**
1. 删姓名 → 改成「学生 A / 学生 B」；  
2. 删学号、手机号、邮箱、证件号；  
3. 删可定位班级的组合信息（如「2024 级汉教 2 班张三」→「某班学生」）；  
4. 只上传题目类型或病句片段，不上传整份档案。

本周实验只用公开课文与通用教学问题；仓库不提交 `.env` / 密钥。
