# 作业 1 · 失败案例会诊（参数错）

> 在整理当堂 3 条成功轨迹（见 `call_trace.md`）之外，补一条真实失败现象与约束改法。  
> 类型：**参数格式错**（讲义失败类型表第 2 行）。

## 原始问句

```
帮我算一下 35*24 等于多少
```

## 失败时的原始模型输出

本机 `qwen2.5:0.5b` 曾输出（非法 / 易错 JSON）：

```
{"tool": "calc", "args": [35*24]}
```

以及后来的变体：

```
{"tool": "calc", "args": [35, 24]}
```

## 当时发生了什么

1. `[35*24]` **不是合法 JSON**（`35*24` 不能直接当数组元素），`json.loads` 失败 → 早期版本把整段当成「普通回答」，**工具根本没执行**。
2. `[35, 24]` 虽能解析，但 `calc` 只吃「一个算式字符串」；若只取 `args[0]`，会变成 `calc("35")` → 返回 `35`，最终答成「等于 35」，**算对了格式、算错了题**。

## 约束改法（已写进 `tool_agent.py`）

| 改法 | 作用 |
|------|------|
| `_repair_jsonish`：把裸算式 `args: [35*24]` 改成 `args: ["35*24"]` | 非法 JSON 也能解析成合法调用 |
| `calc` 执行前：若 `args` 是两个数字，拼成 `"35*24"` | 拆参也能算对 |
| SYS 写明「参数必须是完整算式字符串」 | 减少模型拆参 |
| 工具返回后强制「禁止再输出 JSON」 | 防止小模型拿到结果后继续刷调用 |

## 改后对照（成功轨迹摘要）

见 `call_trace.md` 轨迹 2：模型输出 `args: ["35*24"]` → 工具返回 `840` → 最终回答 `35×24=840`。
